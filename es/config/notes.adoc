`notes.mergeStrategy`::
	Cuál estrategia de fusión a elegir predeterminadamente al resolver conflictos de notas. Debe ser una de `manual`, `ours`, `theirs`, `union` o `cat_sort_uniq`. Predeterminada a `manual`. Ver la sección "ESTRATEGIAS DE FUSIÓN DE NOTAS" de linkgit:git-notes[1] para mayor información sobre cada estrategia.
+
Esta configuración puede anularse pasando la opción `--strategy` a linkgit:git-notes[1].

`notes.<nombre>.mergeStrategy`::
	Qué estrategia de fusión elegir al realizar una fusión de notas en `refs/notes/<nombre>`. Sobreescribe la más general `notes.mergeStrategy`. Ver la sección "ESTRATEGIAS DE FUSIÓN DE NOTAS" en linkgit:git-notes[1] para más información sobre las estrategias disponibles.

`notes.displayRef`::
	Cuál referencia (o referencias, si se especifica más de una vez o un glob), además de lo predeterminado por `core.notesRef` o `GIT_NOTES_REF`, desde las cuales se leerán las notas cuando se muestren los mensajes de confirmación con la familia de comandos `git log`.
+
Esta configuración se puede sobreescribir con la variable de entorno `GIT_NOTES_DISPLAY_REF`, que debe ser una lista de refs o globa separados por punto y coma.
+
Se emitirá una advertencia para referencias que no existan, pero se ignorará silenciosamente un glob que no coincida con alguna referencia.
+
Esta configuración se puede deshabilitar con la opción `--no-notes` de la familia de comandos linkgit:git-log[1], o con la opción `--notes=<referencia>` aceptada por esos comandos.
+
El valor efectivo de `core.notesRef`(posiblemente sobrescrita por `GIT_NOTES_REF`) es implícitamente añadida a la lista de referencias a ser mostrada.

`notes.rewrite.<comando>`::
	Al reescribir confirmaciones con _<comando>_ (actualmente `amend` o `rebase`), si esta variable es `false`, git no copiará las notas del original en la confirmación reescrita. Predeterminada a `true`. Véase también `notes.rewriteRef` más abajo.
+
Esta configuración se puede anular mediante la variable de entorno `GIT_NOTES_REWRITE_REF`, que debe ser una lista de referencias o expresiones generales separadas por dos puntos.

`notes.rewriteMode`::
	Al copiar notas durante una re-escritura (ver la opción `notes.rewrite.<comando>`), determina lo que se debe hacer si la confirmación destino ya tiene una nota. Debe ser una de `overwrite`, `concatenate`, `cat_sort_uniq` o `ignore`. Predeterminada a `concatenate`.
+
Esta configuración puede anularse con la variable de ambiente `GIT_NOTES_REWRITE_MODE`.

`notes.rewriteRef`::
	Al copiar notas durante una reescritura, especifica la referencia (completa) cuyas notas deben copiarse. Puede ser un patrón de coincidencia, en ese caso, se copiarán las notas de todas las referencias que coincidan. También puedes especificar esta configuración varias veces.
+
No tiene un valor por defecto; debes configurar esta variable para habilitar la reescritura de notas. Establece su valor en `refs/notes/commits` para habilitar la reescritura de las notas de confirmación predeterminadas.
+
Se pueden sobreescribir mediante la variable de entorno `GIT_NOTES_REWRITE_REF`. Consulta `notes.rewrite.<comando>` más arriba para obtener una descripción más detallada de su formato.
